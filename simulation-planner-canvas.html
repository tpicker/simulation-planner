GitHub workflow and considerations

Choose where to host

Canvas. Build the activity as a Canvas page when it can work with supported HTML and styling. Ask for clean HTML that follows the Canvas allowlist and uses no custom JavaScript. Canvas HTML Editor Allowlist

GitHub Pages. Host activities that need JavaScript externally and link to them in Canvas. If you embed one, test access and behavior in the course. About GitHub Pages

Build with generative AI

  • Describe the goal, audience, student actions, inputs, expected results, calculation rules, and hosting needs.
  • Build one full student path. Review the content and code and try examples with known answers.
  • Make one change at a time, name behavior to preserve, and retest. Keep the last working version.

Test, publish, and maintain

  • Test. Check accuracy, instructions, links, keyboard access, and readability. Specify what students save or submit and where it goes.
  • Publish. Confirm who can open the activity. Keep student information and passwords out of the project. Add the student link to the simulation and test the full path.
  • Maintain. Assign an owner, record changes, and check the activity before each course offering.

Publish with GitHub Pages

Use this workflow for a tested web app that can be published from a public repository.

  1. Create a new repository. Choose the owner, enter a name, and set visibility to Public.
  2. Add the app files with index.html at the top level and commit the files.
  3. Open the repository’s Settings and select Pages.
  4. Under Build and deployment, set Source to GitHub Actions.
  5. Select Configure for the Static HTML workflow and commit the workflow to the default branch.
  6. Open Actions and confirm that the deployment succeeded.
  7. Return to Settings, then Pages. Select Visit site, test the activity, and add the link to the simulation.

See the site creation guide, the publishing source guide, the workflow template guide, and the Static HTML walkthrough.
